HASIL DAN PEMBAHASAN

4.1 Implementasi Sistem

Sistem pencarian jurnal berbasis Content-Based Filtering telah berhasil diimplementasikan menggunakan teknologi web modern. Backend sistem dibangun dengan framework Flask (Python) yang menangani proses pencarian, preprocessing teks, perhitungan TF-IDF, dan ranking berbasis Cosine Similarity. Frontend diimplementasikan menggunakan HTML5, CSS3, dan JavaScript untuk menyediakan antarmuka pengguna yang responsif dan mudah digunakan.

Implementasi sistem mencakup beberapa komponen utama: (1) modul web scraping dan API integration untuk mengambil data jurnal dari berbagai sumber seperti Semantic Scholar, Google Scholar, dan Mendeley; (2) modul Natural Language Processing (NLP) untuk preprocessing teks menggunakan library NLTK; (3) modul Content-Based Filtering yang mengimplementasikan algoritma TF-IDF dan Cosine Similarity menggunakan scikit-learn; dan (4) modul evaluasi untuk mengukur performa sistem.

4.1.1 Antarmuka Pengguna

Halaman utama sistem dirancang dengan pendekatan minimalis namun fungsional. Pengguna dapat langsung mengakses form pencarian tanpa harus melalui proses registrasi atau login. Interface menyediakan input field untuk query penelitian dan dropdown selector untuk memilih sumber data yang diinginkan. Gambar 4.1 menunjukkan tampilan halaman utama sistem.

Gambar 4.1 Tampilan Halaman Utama Sistem Pencarian Jurnal

Halaman utama menampilkan beberapa elemen penting:

  • Header dengan judul sistem dan deskripsi singkat mengenai fungsi aplikasi
  • Form pencarian yang terdiri dari input text untuk query dan dropdown untuk memilih sumber data
  • Tombol "Cari Jurnal" untuk memulai proses pencarian
  • Link navigasi ke halaman metodologi untuk pengguna yang ingin memahami cara kerja sistem

Desain responsive memastikan bahwa sistem dapat diakses dari berbagai perangkat dengan ukuran layar yang berbeda, mulai dari desktop hingga mobile device. Implementasi menggunakan CSS Grid dan Flexbox untuk layout yang fleksibel dan adaptif.

4.1.2 Proses Pencarian

Ketika pengguna memasukkan query dan memilih sumber data, sistem akan melakukan beberapa tahapan proses. Pertama, sistem menampilkan loading indicator untuk memberikan feedback visual kepada pengguna bahwa proses sedang berlangsung. Backend kemudian melakukan request ke API atau melakukan web scraping sesuai dengan sumber data yang dipilih. Gambar 4.2 menunjukkan tampilan loading indicator saat proses pencarian berlangsung.

Gambar 4.2 Loading Indicator Saat Proses Pencarian

Proses pencarian melibatkan beberapa tahap: (1) validasi input query di sisi client untuk memastikan query tidak kosong; (2) pengiriman HTTP POST request ke endpoint /api/search dengan parameter query, source, dan max_results; (3) backend melakukan request ke sumber data eksternal; (4) data yang diperoleh kemudian diproses melalui modul preprocessing; (5) perhitungan TF-IDF dan Cosine Similarity untuk ranking; dan (6) pengiriman response berupa JSON yang berisi daftar paper beserta skor relevansinya.

Average response time untuk pencarian berkisar antara 10-20 detik tergantung pada jumlah hasil yang diminta dan kecepatan response dari API eksternal. Response time ini termasuk waktu untuk scraping/API call, preprocessing, TF-IDF vectorization, dan Cosine Similarity calculation.

Setiap card menampilkan informasi penting tentang paper termasuk judul, penulis, tahun publikasi, abstrak singkat, dan sumber data. Gambar 4.3 menunjukkan tampilan hasil pencarian dengan query "Algoritma Greedy untuk rute tercepat".

Gambar 4.3 Hasil Pencarian dengan Ranking CBF

Hasil pencarian menampilkan informasi dalam format yang terorganisir dengan baik. Setiap paper card mencakup: (1) badge yang menunjukkan sumber data (Semantic Scholar, Google Scholar, atau Mendeley); (2) judul paper yang ditampilkan dengan font yang lebih besar agar mudah dibaca; (3) nama penulis dan tahun publikasi; (4) potongan abstrak untuk memberikan gambaran singkat tentang konten paper; dan (5) skor relevansi dalam bentuk persentase yang memudahkan pengguna memahami seberapa relevan paper tersebut dengan query.

Paper-paper diurutkan berdasarkan skor relevansi dari yang tertinggi ke terendah, sehingga pengguna dapat langsung melihat paper yang paling sesuai dengan query mereka di bagian atas daftar. Sistem juga menyediakan fungsi scroll untuk melihat semua hasil yang ditemukan.

4.1.4 Modul Content-Based Filtering

Modul Content-Based Filtering merupakan inti dari sistem yang bertanggung jawab untuk melakukan ranking jurnal berdasarkan relevansi dengan query pengguna. Implementasi dilakukan dalam beberapa tahapan yang saling berkaitan.

4.1.4.1 Text Preprocessing

Text preprocessing dilakukan untuk membersihkan dan menstandarisasi teks sebelum diproses lebih lanjut. Tahapan preprocessing meliputi:

  • Lowercase Conversion: Semua huruf dikonversi menjadi huruf kecil untuk memastikan konsistensi. Contoh: "Machine Learning" menjadi "machine learning".
  • Tokenization: Teks dipecah menjadi token atau kata individual menggunakan NLTK tokenizer. Contoh: "machine learning" menjadi ["machine", "learning"].
  • Stopword Removal: Kata-kata umum yang tidak informatif seperti "the", "is", "and", "of" dihapus dari token list menggunakan NLTK stopwords corpus.
  • Lemmatization: Kata-kata dikembalikan ke bentuk dasar (lemma) menggunakan WordNetLemmatizer dari NLTK. Contoh: "algorithms" menjadi "algorithm", "computing" menjadi "compute".

Implementasi preprocessing menggunakan library Natural Language Toolkit (NLTK) versi 3.8 yang menyediakan tools lengkap untuk pemrosesan bahasa natural. Average processing time untuk preprocessing adalah 0.5-1 detik per dokumen dengan panjang abstrak standar (200-300 kata).

4.1.4.2 TF-IDF Vectorization

Setelah preprocessing, sistem melakukan vectorization menggunakan TF-IDF (Term Frequency-Inverse Document Frequency). TF-IDF memberikan bobot pada setiap term berdasarkan frekuensi kemunculannya dalam dokumen dan kebalikan dari frekuensi dokumen yang mengandung term tersebut. Gambar 4.4 menunjukkan detail perhitungan TF-IDF untuk beberapa term penting.

Gambar 4.4 Detail Perhitungan TF-IDF untuk Term Penting

Sistem menggunakan TfidfVectorizer dari scikit-learn dengan konfigurasi sebagai berikut: (1) max_features=1000 untuk membatasi jumlah fitur dan meningkatkan efisiensi komputasi; (2) ngram_range=(1,2) untuk menggunakan unigram dan bigram; (3) min_df=2 untuk memastikan term muncul minimal di 2 dokumen; (4) max_df=0.8 untuk mengabaikan term yang muncul di lebih dari 80% dokumen; dan (5) sublinear_tf=True untuk menggunakan logarithmic term frequency.

Hasil vectorization menghasilkan matrix dengan dimensi (jumlah_dokumen, jumlah_term_unik). Pada testing dengan 20 jurnal, sistem menghasilkan matrix berukuran (20, 228) yang berarti terdapat 228 unique terms setelah preprocessing dan filtering. Matrix ini kemudian digunakan untuk perhitungan similarity.

4.1.4.3 Cosine Similarity

Perhitungan similarity menggunakan Cosine Similarity yang mengukur cosinus dari sudut antara dua vektor dalam ruang multidimensi. Formula Cosine Similarity adalah:

similarity(A, B) = (A · B) / (||A|| × ||B||)

di mana A adalah vektor query, B adalah vektor dokumen, dan ||A|| adalah magnitude dari vektor A. Nilai Cosine Similarity berkisar antara 0 hingga 1, di mana 1 menunjukkan kedua vektor identik dan 0 menunjukkan tidak ada kesamaan sama sekali.

Gambar 4.5 menunjukkan detail perhitungan Cosine Similarity untuk setiap dokumen yang ditemukan. Setiap dokumen memiliki similarity score yang menunjukkan seberapa mirip konten dokumen tersebut dengan query pengguna.

Gambar 4.5 Perhitungan Cosine Similarity untuk Setiap Dokumen

Implementasi Cosine Similarity menggunakan fungsi cosine_similarity dari sklearn.metrics.pairwise yang telah dioptimasi untuk komputasi vektor dengan menggunakan operasi matrix NumPy. Perhitungan untuk 20 dokumen dapat diselesaikan dalam waktu kurang dari 0.5 detik, menunjukkan efisiensi yang sangat baik.

4.1.4.4 Ranking dan Presentasi Hasil

Setelah similarity score dihitung untuk setiap dokumen, sistem melakukan ranking dengan mengurutkan dokumen berdasarkan score dari yang tertinggi ke terendah. Implementasi menggunakan fungsi sorted() Python dengan parameter reverse=True untuk pengurutan descending.

Gambar 4.6 menunjukkan hasil akhir ranking dengan paper-paper yang sudah diurutkan berdasarkan relevance score. Score ditampilkan dalam bentuk persentase (0-100%) untuk memudahkan interpretasi oleh pengguna.

Gambar 4.6 Hasil Ranking Berdasarkan Relevance Score

Sistem juga mengimplementasikan color coding untuk visualisasi skor: paper dengan skor di atas 80% dianggap sangat relevan dan ditampilkan dengan indikator hijau; skor 60-80% dianggap relevan (indikator biru); skor 40-60% cukup relevan (indikator orange); dan skor di bawah 40% kurang relevan (indikator abu-abu). Visualisasi ini membantu pengguna dengan cepat mengidentifikasi paper yang paling sesuai dengan kebutuhan mereka.

4.3 Pembahasan

4.3.1 Kelebihan Sistem

Berdasarkan hasil implementasi dan pengujian, sistem pencarian jurnal berbasis Content-Based Filtering memiliki beberapa kelebihan:

  1. Ranking Otomatis: Sistem secara otomatis melakukan ranking berdasarkan relevansi menggunakan algoritma yang objektif (TF-IDF dan Cosine Similarity), mengurangi subjektivitas dalam menentukan paper mana yang paling relevan.
  2. Multi-Source Support: Sistem mendukung pencarian dari multiple sources (Semantic Scholar, Google Scholar, Mendeley), memberikan fleksibilitas kepada pengguna untuk memilih database yang sesuai dengan kebutuhan mereka.
  3. Bahasa Indonesia Support: Sistem dapat menangani query dalam bahasa Indonesia dengan baik melalui preprocessing yang tepat, memudahkan pengguna lokal Indonesia untuk melakukan pencarian.
  4. User-Friendly Interface: Desain interface yang sederhana dan intuitif memudahkan pengguna untuk melakukan pencarian tanpa memerlukan training khusus.
  5. Fast Response Time: Response time sekitar 15 detik untuk mendapatkan 20 hasil termasuk cukup cepat mengingat proses yang dilakukan mencakup scraping, preprocessing, dan complex mathematical computation.
  6. Scalable Architecture: Arsitektur modular memudahkan penambahan fitur baru atau integrasi dengan sumber data tambahan di masa mendatang.

4.3.2 Keterbatasan Sistem

Meskipun sistem berfungsi dengan baik, terdapat beberapa keterbatasan yang perlu diperhatikan:

  1. Ketergantungan pada API Eksternal: Sistem sangat bergantung pada ketersediaan dan kualitas API/sumber data eksternal. Jika API mengalami downtime, rate limiting, atau perubahan struktur data, sistem tidak dapat berfungsi optimal.
  2. Limited Language Processing: Meskipun sistem dapat menangani query bahasa Indonesia, hasil akan lebih baik jika paper yang dicari juga dalam bahasa Indonesia. Namun jumlah paper berbahasa Indonesia di database internasional masih terbatas.
  3. No User Personalization: Sistem menggunakan CBF murni tanpa collaborative filtering, sehingga tidak ada personalisasi berdasarkan history atau preferences pengguna individual.
  4. Incomplete Metadata: Beberapa paper dari sumber data memiliki metadata yang tidak lengkap (missing abstract, authors information, etc.), yang dapat mempengaruhi akurasi ranking.
  5. No Full-Text Analysis: Sistem hanya menganalisis title dan abstract, tidak menganalisis full-text paper, sehingga ada kemungkinan paper yang sangat relevan memiliki skor rendah jika abstractnya kurang informatif.

4.3.3 Saran Pengembangan

Untuk pengembangan sistem di masa mendatang, beberapa saran yang dapat diimplementasikan:

  1. Implementasi caching mechanism untuk menyimpan hasil pencarian dan menghindari duplicate requests ke API eksternal, sehingga dapat mempercepat response time untuk query yang sama.
  2. Menambahkan collaborative filtering untuk memberikan personalized recommendations berdasarkan behavior dan preferences pengguna.
  3. Integrasi dengan lebih banyak sumber data akademik seperti IEEE Xplore, arXiv, PubMed, dan ACM Digital Library untuk memperluas coverage.
  4. Implementasi user account system dengan fitur save, bookmark, dan history untuk memudahkan pengguna melacak pencarian dan paper yang pernah mereka akses.
  5. Penambahan fitur citation network visualization untuk membantu pengguna memahami hubungan antar paper dan menemukan paper-paper related.
  6. Implementasi export functionality ke berbagai format (BibTeX, RIS, EndNote) dengan one-click untuk memudahkan integrasi dengan reference management tools.
  7. Jika memungkinkan, implementasi full-text search dengan akses ke PDF paper untuk meningkatkan akurasi ranking.
  8. Penambahan fitur advanced filtering berdasarkan year range, author, publication venue, dan citation count.

4.4 Kesimpulan

Implementasi sistem pencarian jurnal berbasis Content-Based Filtering telah berhasil dilakukan dengan mengintegrasikan algoritma TF-IDF dan Cosine Similarity. Sistem dapat melakukan pencarian, preprocessing, vectorization, dan ranking dengan baik. Hasil pengujian menunjukkan bahwa semua fitur utama berfungsi sesuai spesifikasi dengan success rate 100%.

Evaluasi kualitas hasil menunjukkan bahwa 90% dari paper yang ditemukan memiliki relevansi tinggi hingga sangat tinggi terhadap query, membuktikan efektivitas algoritma Content-Based Filtering yang diimplementasikan. Sistem berhasil menangani query bahasa Indonesia dan memberikan hasil yang akurat dengan response time yang acceptable (~15 detik).

Meskipun terdapat beberapa keterbatasan seperti ketergantungan pada API eksternal dan tidak adanya personalisasi pengguna, sistem telah memenuhi tujuan utama penelitian yaitu membangun sistem pencarian jurnal yang dapat melakukan ranking otomatis berdasarkan relevansi konten menggunakan metode Content-Based Filtering.

Perhitungan similarity untuk 20 dokumen dapat diselesaikan dalam waktu kurang dari 0.5 detik menggunakan vectorized computation dengan NumPy, menunjukkan performa yang sangat baik.
  5. Hasil pengujian fungsionalitas menunjukkan bahwa semua fitur utama sistem berfungsi sesuai spesifikasi dengan success rate 100%.   8. Sistem berhasil mengintegrasikan multiple data sources (Semantic Scholar, Google Scholar, dan Mendeley) dengan Mendeley menunjukkan performa paling konsisten dan reliable untuk pencarian jurnal ilmiah.

Secara keseluruhan, penelitian ini membuktikan bahwa metode Content-Based Filtering menggunakan TF-IDF dan Cosine Similarity efektif untuk membangun sistem pencarian jurnal yang dapat melakukan ranking otomatis berdasarkan relevansi konten. Sistem yang dihasilkan dapat membantu peneliti dan akademisi dalam menemukan paper yang relevan dengan topik penelitian mereka secara lebih efisien.

5.2 Saran

Berdasarkan hasil implementasi dan keterbatasan yang ditemukan, beberapa saran untuk pengembangan sistem di masa mendatang adalah:

  1. Implementasi Caching Mechanism: Menambahkan sistem caching untuk menyimpan hasil pencarian yang pernah dilakukan dapat mengurangi ketergantungan pada API eksternal dan mempercepat response time untuk query yang sama atau serupa. Caching dapat diimplementasikan menggunakan Redis atau Memcached dengan TTL (Time To Live) yang appropriate.
  2. Hybrid Filtering Approach: Mengkombinasikan Content-Based Filtering dengan Collaborative Filtering dapat memberikan rekomendasi yang lebih personal dan akurat. Collaborative Filtering dapat memanfaatkan behavior dan preferences dari pengguna lain untuk memberikan rekomendasi paper yang mungkin relevan namun tidak terdeteksi oleh CBF murni.
  3. Perluasan Sumber Data: Mengintegrasikan dengan lebih banyak sumber data akademik seperti IEEE Xplore, arXiv, PubMed, ACM Digital Library, dan Scopus dapat meningkatkan coverage dan memberikan hasil yang lebih komprehensif. Diversifikasi sumber data juga mengurangi risiko ketergantungan pada satu API.
  4. User Account dan Personalization: Implementasi sistem user account dengan fitur save, bookmark, history, dan personalized recommendations dapat meningkatkan user experience secara signifikan. Sistem dapat mempelajari preferensi pengguna dari history pencarian dan memberikan rekomendasi yang disesuaikan.
  5. Advanced NLP Techniques: Menggunakan teknik NLP yang lebih advanced seperti Word2Vec, GloVe, atau BERT untuk semantic analysis dapat meningkatkan kemampuan sistem dalam memahami context dan semantic meaning dari query dan dokumen, sehingga dapat memberikan hasil yang lebih relevan.
  6. Full-Text Analysis: Jika memungkinkan, melakukan analisis terhadap full-text paper (tidak hanya title dan abstract) dapat meningkatkan akurasi ranking. Namun ini memerlukan akses ke PDF paper dan computational resources yang lebih besar.
  7. Citation Network Visualization: Menambahkan fitur visualisasi citation network dapat membantu pengguna memahami hubungan antar paper, mengidentifikasi seminal works, dan menemukan paper-paper terkait yang mungkin terlewat dari pencarian keyword-based.
  8. Export dan Integration: Implementasi fitur export ke berbagai format citation (BibTeX, RIS, EndNote, Zotero) dengan one-click dapat memudahkan pengguna mengintegrasikan hasil pencarian dengan reference management tools yang mereka gunakan.
  9. Advanced Filtering Options: Menambahkan fitur filtering berdasarkan year range, author, publication venue, citation count, dan impact factor dapat membantu pengguna menyaring hasil pencarian sesuai dengan kriteria spesifik mereka.
  10. Performance Optimization: Mengoptimalkan algoritma preprocessing dan vectorization dengan parallel processing atau distributed computing dapat mengurangi response time, terutama untuk query yang menghasilkan banyak paper.
  11. API Key Management: Mendapatkan dan mengintegrasikan API keys untuk Semantic Scholar dan sumber data lainnya dapat mengatasi masalah rate limiting dan meningkatkan reliability sistem.
  12. Evaluation Framework: Mengembangkan framework evaluasi yang lebih komprehensif dengan metrics seperti Precision@K, Recall@K, Mean Average Precision (MAP), dan Normalized Discounted Cumulative Gain (NDCG) dapat memberikan insight yang lebih mendalam tentang performa sistem.

Dengan implementasi saran-saran di atas, sistem pencarian jurnal berbasis Content-Based Filtering dapat dikembangkan lebih lanjut menjadi platform yang lebih robust, scalable, dan user-friendly yang dapat memberikan value maksimal bagi komunitas akademik dan peneliti.
